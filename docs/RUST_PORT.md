# Перенос WoW Classic Arena на Rust: всё, что нужно знать

Документ для разработчика (и его Claude), который будет переносить игру с JavaScript/Three.js на Rust. Написан по состоянию на версию **0.0.126** (29.10.2026). Владелец проекта и геймдизайнер: Сергей (GitHub `SWITER92`). После переноса работа продолжится на новом движке, поэтому главное требование: **сохранить поведение и все правила боя один в один**, а также совместимость с сервером и админкой.

---

## 1. Что это за игра

- Браузерная PvP-арена в стиле World of Warcraft 1.12 (классика): бои 1 на 1, 2 на 2, 3 на 3 против ботов или живых игроков.
- Классы: воин, маг, разбойник, паладин, жрец. У каждого настоящие деревья талантов 1.12 (51 очко), способности со стойками/скрытностью, ауры, DoT/HoT, контроль с убыванием (DR).
- Карта: арена Награнда (TBC), извлечена из клиента. Модели персонажей, эффекты заклинаний (M2-частицы), иконки и звуки взяты из клиента WoW.
- Сайт: https://switer92.github.io/WoW_Classic_Arena/ (GitHub Pages, ветка `main`, `index.html` в корне).
- Свой сервер: `wowarena92.duckdns.org` (VPS Ubuntu 24.04, Caddy + Node.js). Комнаты для сетевой игры, серверные бои, админка баланса.

### Правила проекта, которые нельзя нарушать
1. **Кулдауны, длительности, время каста, дальность и стоимость способностей = данные 1.12 Spell.dbc.** Исключения задаёт только Сергей (сейчас: Превращение 10 с, Ошеломление 20 с / 10 м, Ослепление 15 м).
2. Камера и управление как в WoW. **Никогда не добавлять «умную» камеру, которая сама поворачивается за персонажем** (Сергей это явно отверг).
3. Боты — временная заглушка до живых игроков. Не вкладываться в их ИИ.
4. Версия игры: каждая выкладка +0.0.001 (`version.txt`, показывается в меню справа внизу).
5. Баланс правится через админку без пересборки: игра должна принимать частичный JSON поверх своих значений по умолчанию (см. раздел 6).
6. Интерфейс и тексты на русском.

## 3. Архитектура движка (src/p3.js)

Один глобальный модуль, состояние в глобальных переменных. Разделы файла:

| Раздел | Что делает |
|---|---|
| ТАЛАНТЫ | `rk(u,id)` ранг, `tv(u,id)` значение таланта; общие модификаторы `k:"add"/"mul"` применяются к полям способностей автоматически |
| СПОСОБНОСТИ | `META[id]`: школа, цель, ГКД, требования (стойка, скрытность, со спины…), `exec(u,t,a)` — что делает. `eff(u,id)` = данные способности с учётом талантов |
| СЦЕНА | Three.js r128, загрузка карты, свет, камера |
| СОСТОЯНИЕ | `class Unit` (hp, res, auras, cds, stance, talents, pos/y/facing…), сложности ботов `DIFF` (новичок/гладиатор/чемпион/манекен) |
| БОЙ | `canUse` (все условия применения, порядок важен), `tryUse`, `pay`, `damage`, `heal`, `addDot`, `cc` (контроль с DR), `addAura`, крит/промах/уклонение/парирование/блок, броня |
| БОТ | `class Bot` — простая логика по приоритетам |
| ЧАСТИЦЫ / ЭФФЕКТЫ | Простые эффекты + M2-эффекты из `m2fx.js` |
| ИНТЕРФЕЙС | Рамки, полосы каста, ауры, всплывающий урон, неймплейты |
| ПАНЕЛИ ДЕЙСТВИЙ | Раскладка панелей по «страницам» (свои для каждой стойки/скрытности), бинды |
| ВВОД | Управление как в WoW |
| МЕНЮ И РАУНДЫ | Экран выбора персонажа, подготовка, отсчёт, конец раунда |
| СЕТЕВАЯ ДУЭЛЬ | Комнаты, лобби, протокол хост/клиент |
| ЦИКЛ | `step(dt)`: ввод → боты → движение → коллизии → `updateUnit` (ауры, тики, реген) |

### Ключевые правила боя (все числа в `DEF.general`, правятся в админке)
- ГКД 1,5 с. Дальность ближнего боя 5 м + `reach` 0,78.
- Промах ближнего боя 5% (+19% автоатаке при двух оружиях), уклонение по классу, парирование только спереди (воин/разбойник/паладин 5%), блок щитом снижает урон на 40%.
- Броня: снижение = броня / (броня + 5500) (формула 1.12 для 60 уровня), физ. урон ×1,5 (компенсация).
- Криты: ближний ×2, заклинания ×1,5. Сила заклинаний (1.12): прибавка = сила × каст/3,5; мгновенные 1,5/3,5; канал делится на тики; АоЕ треть; доты длительность/15.
- Убывание контроля: окно 18 с, шаги 1 / 0,5 / 0,25 / 0; категории в `cc(...,{drc})`.
- Реген: правило 5 секунд (`fsr`), вне боя ×`oocManaMult`, ярость убывает вне боя.
- Отсчёт перед боем 5 с (`prep`): можно только бафы на себя и лечение союзников, без перемещения; при открытии ворот HP и мана полные.
- «Усталость» (dampening) с 60-й секунды, +1%/с до 90%.
- Доты тикают раз в 3 с (Огненный шар, Священный огонь, Рваная рана, Воспламенение — 2 с); тики не продлевают бой и не сбивают каст.
- Ледяная глыба и Божественный щит снимают все дебаффы и работают под любым контролем.
- Дух искупления (жрец): при живом союзнике 10 с неуязвимым духом, лечит бесплатно.
- Мелкие правила Сергея: Исчезновение снимает все дебаффы, Парализующий удар даёт приём серии, боты не преследуют невидимых, мгновенные заклинания дальнего боя не требуют смотреть на цель.

### Движение и камера (константы из клиента 1.12)
Поворот 180°/с (×0,75 в движении и в прыжке), назад ×0,643, прыжок 7,96 при гравитации 19,29, камера смотрит в точку головы, FOV 90° по диагонали, зум 1 ярд за шаг со скоростью 8,33 ярд/с, столкновение камеры с колоннами/стенами/полом. Источник констант: репозиторий `OutThisLife/azeroth-survivors-re` (MIT/Apache, Rust + Bevy, клиент 1.12), файлы `crates/benilla-app/src/player/state.rs`, `camera*.rs`, `mover.rs`.

### Всплывающий урон (по `combat_text/law.rs` оттуда же)
Золотой FFDE00 для заклинаний, белый для ближнего боя; обычные цифры поднимаются на 2 ед. за 1,5 с; криты не поднимаются, а «выпрыгивают» 0,1→2→1; максимум 4 на юнит.

## 4. Сеть

Хост-авторитетная схема: всё считает хост, клиенты шлют ввод и получают снимки.

- Транспорт: сначала `wss://wowarena92.duckdns.org/arena?room=ABCD&role=host|client` (наш relay), если недоступен — PeerJS (WebRTC). `?ws=` переопределяет адрес.
- Серверный бой: `POST /arena/api/create` запускает `server/sim.js` (jsdom + three), который подключается к relay как хост. Если не вышло — хостом становится браузер создателя.
- Сообщения (JSON, поле `t`):
  - клиент → хост: `hello` (версия, ник, класс, таланты, яды), `ready`, `team`, `in` (позиция x/z/y, facing, движение, прыжок, цель, ~25 раз/с, «быстрый» неупорядоченный канал), `use` (id способности), `ping`.
  - хост → клиент: `lobby`, `start` (состав, свой индекс, отсчёт), `snap` (состояние всех юнитов: hp, ресурс, ауры с временем, каст, позиция), `ev` (события: эффекты, тексты урона, звуки), `full`, `oldver`, `bye`, `po`/`pg`.
- Хост принимает позицию клиента, но проверяет скорость (античит, `antiCheat`: 0 = только журнал, 1 = возвращать) и всегда ограничивает высоту прыжка.
- Комнаты до 4 людей (+ боты), публичные комнаты видны в лобби (`GET /arena/api/lobby`).

## 5. Сервер (VPS)

- Node.js 22, `relay.js` слушает 127.0.0.1:8080, Caddy даёт https. Служба `arena-relay`.
- Автообновление: таймер `arena-update` каждые 2 мин делает `git pull` и перезапускает службу, только если менялась папка `server/`. Секретов в репозитории нет.
- Данные: `/opt/arena/data/` — `balance.json` (текущие правки), `history/N.json` (все версии), `admin.json` (хеш пароля, задаётся `sudo arena-admin-password`), `feedback.json`, `feedback-ban.json`, `roadmap.json`, `stats.json`.
- HTTP API (`/arena/api/…`): публичные `GET balance`, `GET defaults`, `GET roadmap`, `GET lobby`, `POST ping` (онлайн), `POST feedback` (антиспам: текущая версия, ≥1 сыгранный бой, ловушка, 3 с, лимиты), `POST create`; для админа (Bearer-токен после `POST login`) — `POST balance`, `GET history`, `POST rollback`, `GET overview`, `GET stats`, `GET feedback`, `POST feedback/set`, `POST roadmap`.

**Сервер переписывать не обязательно.** Если новый клиент сохранит формат баланса и сетевой протокол (или мы договоримся о новом протоколе и обновим relay), сервер и админка останутся.

## 6. Данные баланса (src/p2.js) — самое важное для совместимости

```
DEF = {
  general: { gcd, prep, drWindow, drSteps[], meleeRange, reach, meleeCritMult, spellCritMult, spellMiss, meleeMiss, dwMiss,
             armorK, physMult, parry{warrior,rogue,paladin}, pushback[], blockReduce, backpedal, fsr, fsrManaPct, ... },
  common:  { abilities: { trinket, food } },
  warrior: { armor, hp, maxRes, startRes, crit, dodge, ap, swing{interval,dmg[2],rage}, abilities:{ id:{name, cd, cost, range, cast, dur, dmg, ...} } },
  mage | rogue | paladin | priest: { ... sp (сила заклинаний), manaRegen | energyRegen, ohSwing (разбойник) ... },
  talents: { <класс>: { <ветка>: { name, list: { id: { n, t (ряд), c (столбец), max, v (значение или массив по рангам), k, a, f, sg, req, reqr, d (описание с {x}) } } } } }
}
```

- Админка хранит **только изменённые числа** (частичный объект с теми же путями) и отдаёт их в `GET /arena/api/balance`. Игра применяет их поверх `DEF` между раундами (`safeMerge`: только числа и массивы чисел той же длины).
- В Rust: держите `DEF` как данные (JSON/RON, сгенерированные из `src/p2.js`), а не как константы в коде. Тогда админка продолжит работать без изменений.

## 7. Ассеты и как их получали

- Источник: клиент WoW 1.12 (`patch.MPQ` и др.) и экспорт Сергея через **wow.export** (TBC/Wrath Classic) для карты Награнда, ворот и HD-нежити.
- `tools/m2x`: `mpq.py` (чтение MPQ), `dbc.py`/`dbcq.py` (Spell.dbc, Talent.dbc, SpellVisualKit…; поля Spell.dbc 1.12: 18 индекс каста, 19/20 кд, 30 индекс длительности, 36 индекс дальности, 32 стоимость, 156 % базовой маны), `ex.py` + `pack.py` (M2 v256 → `assets/fx/m2fx.json` + текстуры webp), `mkvis.py` (визуал заклинания по id).
- Модели персонажей: человек (воин, паладин) и нежить HD (маг, разбойник, жрец) в glb (base64 в `.glb.txt`), анимации по именам как в клиенте; оружие/наплечники крепятся к точкам крепления M2.
- Карта: `assets/nagrand/map.bin` — геометрия групп WMO + навигационная сетка 0,5 ярда (пол/блок/потолок/SDF) для `groundAt`, LOS и поиска пути.
- Для Rust удобнее читать исходные форматы напрямую (M2/WMO/BLP/DBC) — это уже умеет `azeroth-survivors-re` (крейты `benilla-m2`, `-wmo`, `-blp`, `-mpq`, `-formats`). Но **отдавать в браузер нужно наши подготовленные файлы**, а не MPQ клиента (их нельзя распространять).

## 8. Рекомендуемый план переноса

Стек: **Rust + Bevy, сборка в wasm** (как у `azeroth-survivors-re`, можно брать оттуда загрузчики форматов, камеру и движение с указанием лицензии). Одна кодовая база для браузера и, при желании, десктопа.

1. **Ядро боя без графики** (крейт `arena-core`): `Unit`, ауры, `canUse`/`tryUse`/`damage`/`heal`/`cc`/DR, таланты, реген, боты. Детерминированный шаг `step(dt)`. Данные `DEF` из JSON.
2. **Сверка с JS-версией**: прогнать одинаковые сценарии (фиксированный seed) в обеих версиях и сравнить урон/лечение/исходы. В JS есть тесты-сценарии (`t7.js` — пары классов 1 на 1, `t2v2h.js` — 2 на 2; Playwright). Перенести хотя бы пары 1 на 1.
3. **Сцена**: карта Награнда, модели, анимации, камера и управление WoW.
4. **Интерфейс**: экран выбора персонажа, HUD, панели со страницами стоек, книга способностей, окно талантов, неймплейты, всплывающий урон, окна «Отзыв», «Дорожная карта», кнопка «Донат».
5. **Эффекты**: M2-частицы/ленты по `m2fx.json` (или прямо из M2).
6. **Сеть**: тот же протокол поверх WebSocket к нашему relay; серверный бой — запускать ядро нативно на сервере вместо jsdom (большой выигрыш по памяти и пингу).
7. **Баланс из админки**: `GET /arena/api/balance` поверх `DEF`, как сейчас.

### Критерии «перенос готов»
- Все 5 классов и все таланты работают как в версии 0.0.126 (прогон сценариев совпадает в пределах случайности).
- Онлайн-бой через наш сервер, лобби, комнаты до 4 человек.
- Админка меняет баланс без пересборки.
- Версия, отзывы, дорожная карта, статистика онлайна работают (используют существующие API).
- 60 FPS на среднем ноутбуке в браузере.

## 9. Что важно не потерять (мелочи, которые легко сломать)

- Порядок проверок в `canUse`; для отрисовки кнопок есть режим `ui`, игнорирующий кулдаун/ГКД/каст (тусклая кнопка = нельзя по условию, синяя = нет ресурса, красная клавиша = далеко).
- Раскладка панелей отдельно для каждой стойки и скрытности; хранится в `localStorage` (`arena-bars-v1`, `arena-binds-v1`, `arena-settings`, `arena-talents-v1`, `arena-wins`).
- Свои «страницы» панели у воина (3 стойки) и разбойника (скрытность).
- Хост в фоновой вкладке не должен замораживать бой (сейчас тик через Worker).
- Клиент старой версии не может войти к хосту новой (`GAME_VER`).
- Тексты интерфейса на русском, имена способностей — как в русском клиенте.
